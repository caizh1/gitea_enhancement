# 群组导航使用说明

## 入口与创建

登录后，在首页右侧选择“群组”。“我的群组”默认折叠，点击箭头展开直接子群组，点击名称进入主页。“＋”创建顶级群组；“查看全部群组”进入完整列表。

进入父群组后，点击“创建子群组”。短路径输入框下实时显示完整路径；创建成功后进入新群组。点击“创建仓库”时自动选择当前群组，私有父组下默认创建私有仓库。现有个人仓库入口保留。

群组主页默认只列直接子群组与直属仓库。点击子群组箭头继续展开；搜索查找可访问后代，结果显示完整路径；清空搜索恢复之前展开状态。支持活动／非活动、名称／创建时间／更新时间及升降序。每层默认二十项，点击“加载更多”继续。

## 成员和继承

父群组授权会向下继承。在子群组“成员”页，同一用户显示一行，展开来源可见角色、能力和到期时间。继承来源应点击“前往来源修改”，不能在子组删除父组授权。

“编辑直接授权”自动填写已有用户名、角色、到期日期及自定义角色；移除直接授权后，其他继承、共享或团队来源继续生效。原生团队仍从团队页面管理，分单元授权不会被转换为通用角色。无法用单一角色描述的组合显示“组合授权”。

普通成员只能查看自己的授权来源。管理者可查看完整列表并搜索、按来源筛选；操作提交时重新检查权限和修订号。

## 权限边界

只有子群组权限时，首页保留该子群组独立入口。无权祖先仅显示已授权路径中的短名称，不提供链接。仅获仓库授权的用户可进入受限路径入口，只浏览已获权仓库，不会获得父组成员、共享或设置权限。公开可读不等于加入“我的群组”；管理员可访问全部资源也不会自动成为全部群组成员。

共享、自定义角色、原生团队和继承使用已有权限模型。每次展开、搜索和进入页面重新鉴权，不新增权限表或改变稳定 ID。页面失败显示错误和重试入口；登录失效后需要重新登录。

## 更新已有 Demo

1. 保留原安装目录、`.env`、`secrets/`、Compose 项目名和两个数据卷；维护窗口先停止业务写入并保存备份。
2. 将新包解压覆盖到原目录。归档不含 `.env`、账号凭据或数据卷内容，不要删除这些现有文件。
3. 在原目录执行 `bash 安装并启动.sh`。脚本导入镜像并替换容器，继续使用现有地址、密码和数据卷；使用过自定义 `COMPOSE_PROJECT_NAME` 时继续使用同一值。
4. 等待脚本确认就绪。登录后刷新浏览器，打开“群组”，核对原群组及仓库。

本次程序使用原数据库结构版本 370，不是从官方旧版到治理版的存量迁移验收。真正 Linux 宿主机、容量、持续运行及 Manager 兼容仍按约定后置。
