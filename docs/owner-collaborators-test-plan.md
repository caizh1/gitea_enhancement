# 仓库 Owner 与协作者测试方案

## 验收口径

本方案以用户确认的权限规则为预期，不使用生产权限函数计算期望值。下表是需求用例目录，不是通过记录。每个角色、来源、入口和浏览器展开为独立执行记录；某个子场景通过不能代表整个编号通过。

测试使用隔离账号和实例，管理员只准备样本。主部署环境为 Ubuntu 24.04 amd64、PostgreSQL 17.11；SQLite 只承担快速模型和服务回归。浏览器要求 Chromium、Firefox，视口为 1440×900、768×1024、390×844，并补充 200% 缩放及键盘操作。测试不涉及 Manager、AI 审查及迁移。

固定样本包括个人、原生组织、两层嵌套群组、兄弟群组、邀请群组、多来源、三种可见性、保护分支项目。账号覆盖六种项目角色、群组 Minimal Access、受限、站点管理员、审计、停用、禁登、待接受邀请账号；来源覆盖个人、Owners 团队、祖先、直接、共享、临时 Owner。规模为 0、1、99、100、101、205、1001 人，另有 205 人中 103 位 Owner 的跨页过滤样本。

## 独立权限预期

| 私有项目角色 | 查看成员 | 读取代码 | 普通分支推送 | 管理普通成员 | 管理 Owner | 共享及生命周期 |
|---|---|---|---|---|---|---|
| 无授权或仅群组 Minimal Access | 否 | 否 | 否 | 否 | 否 | 否 |
| Guest | 是 | 否 | 否 | 否 | 否 | 否 |
| Planner | 是 | 否 | 否 | 否 | 否 | 否 |
| Reporter | 是 | 是 | 否 | 否 | 否 | 否 |
| Developer | 是 | 是 | 是 | 否 | 否 | 否 |
| Maintainer | 是 | 是 | 是 | 最高 Maintainer | 否 | 否 |
| Owner | 是 | 是 | 是 | 最高 Owner | 是 | 是，仍受策略约束 |

Planner 具有议题管理及 PR 读取能力；自定义角色逐项校验。普通团队管理员和普通能力组合不得升级 Owner。站点管理员有管理能力，但不自动出现在项目成员中。群组 Minimal Access 不能获得私有项目访问，独立 Guest 授权可以；公开和内部基础可见性另算。共享逐层取能力交集，再合并独立来源。项目 Owner 不自动获得组织、兄弟项目及目标转入组织权限。

## 可执行用例表

每行的前置条件必须在执行前核对；涉及撤权的用例同时保存变更前后来源和实际操作结果。默认使用有效账号、未到期授权、没有其他来源的私有项目，除非行中另有说明。

| NAV-01 | 六种项目角色分别登录 | 从首页、项目列表、搜索进入项目 | 均能发现有权项目，不依赖手输 URL |
| NAV-02 | 六种角色位于项目页 | 点击协作者，再尝试设置入口 | 成员可查看协作者，不额外获得设置权限 |

| NAV-05 | Guest，项目仅启用代码单元 | 从项目页进入成员页并读取代码 | 成员入口可达，代码拒绝 |

| VIEW-07 | 停用、禁登、过期、待接受邀请 | 查看状态并尝试访问 | 不计有效永久 Owner；邀请未接受无访问权 |

## 执行方式

1. Go 模型/服务测试：`go test -json -count=1 -tags 'sqlite sqlite_unlock_notify' ./services/governance ./models/governance ./models/perm/access ./services/repository ./services/user ./modules/repository ./services/context ./routers/api/v1/repo ./routers/web/repo/setting`。
2. 前端交互测试：`pnpm exec vitest run web_src/js/features/repo-members.test.ts`。
3. 实际部署：先准备独立 Ubuntu 实例并确认版本接口就绪，执行 `node tools/test-owner-collaborators.mjs`。配置仅经标准输入传入 JSON，字段为 `url`、`admin.username`、`admin.password`、`sshPort`、`output` 和可选 `baseline`。只允许本机或本机转发地址，防止误操作生产。不要把真实配置写入仓库或终端历史。
4. 部署脚本会创建独立前缀账号/项目、真实 PAT 和临时 SSH 密钥；密钥在结束时删除。请使用可销毁的实例，脚本不会删除其他项目。脚本退出码非零意味着失败或阻塞。账号数据保留在隔离实例便于复查，验收结束销毁实例。
5. 每次独立运行编号，输出脱敏请求状态、每个子场景、耗时、截图及报告。旧记录不覆盖。不把测试准备错误当成产品权限缺陷；两者分别归因。

## 证据及完成标准

每条执行记录关联编号、前置条件、操作者、步骤、独立期望、实际、状态、耗时、证据。Go JSON 中父测试和子测试不能重复计算为独立用例数。缺少指定浏览器或目标部署结果时标记未执行/阻塞，不拿本机 SQLite 代替 PostgreSQL。

权限、Owner 保护、隐私、撤权和事务关键用例必须全部通过后才能宣称整体验收完成。P0/P1 对抗审查单独给结论；P2/P3 不变成 P1，但已失败的功能用例也不能改成通过。人工维护者需仅凭页面回答五个问题：谁是 Owner、来源、修改入口、为何不可改、撤销后剩余权限。记录旧/新流程的操作数、耗时、判断次数；未实测不能宣称减少人工 80%。
