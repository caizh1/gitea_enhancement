## 已冻结的共同规则与差异

| 编号 | 决定 | 理由及边界 |
| --- | --- | --- |
| D-01 | 复用基础授权解析，不统一继承算法。 | 分别处理实时继承、创建时复制、聚合展示和不可放宽上限；共享只授予访问，不引入被邀请群组配置。 |
| D-02 | 操作权、使用权和来源管理权分开。 | 父级 Owner 管理后代；子级管理者不能修改父级配置；来源路径、计数和自动补全也须鉴权。 |
| D-03 | 变量与凭据按仓库、最近群组、祖先顺序生效。 | 保留实例 Variables；不新增实例 Secrets；保留 fork、可信引用和复用工作流限制，Secret 列表与审计无明文。 |
| D-04 | 强制工作流与令牌上限属于明确增强。 | 已配置的强制检查用来源和真实执行记录证明，不能用同名状态代替；祖先令牌绝对上限取交集。未配置策略不产生全局阻断。 |
| D-05 | I-01 先修确定的领取／转移时序。 | 候选扫描非授权；同一短事务绑定当前范围、任务、Runner 和凭据选择，提交为披露授权点。事务内禁止网络和 Git。 |
| D-06 | 转移前的工作流不自动信任目的范围。 | 优先取消旧等待任务并在新范围可信触发；执行中、专属 Runner、部署密钥等未能安全迁移时，服务端拒绝并给出解除条件。历史已完成任务本身不永久阻止转移。 |
| D-07 | 不声称追回已披露内容。 | 披露授权前失效必须拒绝；之后的令牌、artifact 等访问仍检查当前权限；已发送凭据、邮件和已下载内容不能承诺收回。 |
| D-08 | API 最小扩展。 | 复用组织接口和 `/api/v1/governance`，按需增加来源、继承／覆盖状态、原因、允许操作、修订号；有效查询与来源修改分开。 |
| D-09 | Runner 协议无必要不变更。 | 仅服务端范围修复不要求无理由升级所有 Runner；真正依赖新安全能力时才协商、拒绝不兼容任务并交付配套组件。 |
| D-10 | 暂不前移群组机器凭据产品。 | 当前文档有独立非管理员 Review 机器人，但尚无证据证明现有安全凭据不能满足一期。不能称其为已交付群组凭据，也不能用 Owner PAT 替代。 |
| D-11 | Hook 保留事件时范围和配置版本边界。 | 按 Hook ID 去重；停用／删除和最终投递授权排序，重投重新鉴权；不同 Hook 相同 URL 仍分别发送。 |
| D-12 | 标签独立 ID，产物归属独立。 | 同名标签不覆盖；转移不能静默删除历史。包、OCI、artifact、Release 与 LFS 的聚合展示不改变所有权或授权。 |
| D-13 | 来源组织标签的关联或历史无法保留时，当前转移组合服务端拒绝。 | 已复现原生转移删除当前关联和标签操作历史。首批移除破坏性删除，在同一事务内检查并返回冲突；仓库本级标签仍可正常转移。不是完整祖先标签迁移方案。 |
| D-14 | Runner 注册令牌的读取、生成和轮换重新检查当前管理权。 | Web/API 中间件取得的旧权限快照不足以授权披露；复用治理短事务，不新增令牌平台。CLI 实例管理入口保持原有边界。 |
| D-15 | 群组改变父级与仓库转移均更新 Actions 单调范围修订，失效旧 Run／定时计划。 | 同根移动也可能丢失原继承管理权；移出再移回不能恢复旧信任。存在运行中任务、群组／仓库专属 Runner、部署密钥时先拒绝；纯路径改名不重置 Runner 信任。新范围需要可信新触发或重新检测计划。 |
| D-16 | 调度系统身份必须绑定当前持久计划；重跑使用本次 Attempt 的触发者。 | 不把系统 Actions 身份当普通数据库用户，也不无条件信任系统 ID。检测快照、计划版本、Run 最终入库及任务消费者须一致；旧检测不能删除新范围计划。新增迁移 371，不建设平行调度系统。 |
| D-17 | 部署密钥创建／删除在写事务中复核当前仓库 Admin。 | 已存在密钥阻止转移不足以防住旧请求在转移后插入密钥；Web/API 复用现有权限，SSH 文件同步仍在提交后。 |
| D-18 | 工作流来源的可执行性与强制配置分开。 | 归档、待删除或移出来源范围后禁止新执行及凭据使用，但不能因来源不可用让已配置的强制要求消失；来源范围修订及注册信任另行重检。 |
| D-19 | 服务端合并的 post-receive 补写仅继承精确匹配的持久授权。 | 检查仓库、PR、操作者、单引用及旧/新提交；保留原占用直至 Git 结果核对，不能用移除占用绕过冲突。修复同时恢复 Actions 与定时计划通知。 |
| D-20 | 统一工作流注册、要求修改和移除在实际写入时复核来源管理者。 | 路由的旧身份不授权后续写入；Git 解析在短事务外，提交时重新检查来源范围和当前权限，并遵守治理资源占用。 |
| D-21 | 返回仓库自己的原存储路径不算其他仓库占用。 | 群组层保留原物理目录；转回原归属、改回原名时先检查真实数据库冲突，仅排除该仓库自身的物理目录。不能放宽其他目录或仓库的占用。 |
| D-22 | 受保护 Secret 当前实现仅认可受信事件的当前受保护分支 HEAD。 | `push`、持久定时和手动触发仍检查当前分支及提交；排队期间已被新提交替代的旧运行不下发受保护凭据。此为当前保守实现限制，不是已核实的 GitLab 等价语义；其他事件、受保护标签及完整引用生命周期仍须按矩阵验收。真实旧提交拒发与稳定 HEAD 的 API／Git 正例见[分支保护证据](../outputs/group-subgroup-phase1-20260923/api-branch-protection-evidence.md)。 |
| D-23 | 保留现有跨仓作业 token 只读集合，不扩大写权限或默认开放 Actions 产物。 | 当前 `MakeRestrictedPermissions` 只保留 Code／Packages／Releases 的 read，Actions 为 none；真实同 Owner allow-list Code 读已通过，跨仓产物被拒。v3 runtime 还限定同 Run，官方 v4 action 在当前 Runner 组合失败。此为明确现有差异，不能把跨仓产物正例写为已完成，也不因该失败把必选常用产物访问整体移至二期。 |
| D-24 | 原始完整方案的群组／成员 Webhook 事件独立保留。 | 第一期开工冻结只承诺已有仓库事件；完整事件目录、载荷、发生时范围、投递及撤权验收仍是后续独立开发项，不能把仓库 Hook 继承记为该项完成。 |
| D-25 | 原始完整方案的子树制品聚合独立保留。 | 一期允许资源定位及原生管理入口；跨子群组聚合、权限过滤计数／分页和清理联动仍是后续独立开发项，不能用导航链接或单协议下载替代。 |
| D-26 | 原生 OAuth／屏蔽的写入按当前身份和生命周期检查。 | OAuth 创建、编辑、轮换在归档／待删时禁止；当前 Owner 删除应用、屏蔽和备注属于撤权或非扩权操作，可继续；解除屏蔽拒绝。个人 API 不接受 sudo 组织身份充当个人应用所有者。 |

后置新增能力：完整机器身份／群组令牌平台、完整自定义角色编辑器、LDAP 控制台、新的群组 2FA／成员锁／fork 策略、部署审批、复杂环境匹配与文件凭据、完整 Push Rules／签名／CODEOWNERS 扩展、群组里程碑／看板、跨仓批量编辑、高级搜索、模板中心、全部连接器、统一制品清理、高级审计流、无停顿跨根移动、企业身份／合规／安全扫描／研发分析。现有能力受公共改动影响时仍须回归，不以本段豁免。

受保护 Secret 是一期保守差异：只对当前受保护可信分支的 push／手动／定时下发，PR、PR target、fork 和标签不下发该类 Secret；普通 Secret 继续既有 fork／复用限制。GitLab 19.4 在特定双方受保护 MR 条件下允许的能力没有在一期宣称对齐。祖先工作流强制门禁、作业 token 逐级绝对上限继续作为明确增强。

## 验收基准与人工任务冻结

- 功能数据：两个根，根为第一层的三层子树及兄弟组，至少十仓；父／子 Owner、仓库管理员、开发者、只读、共享、无关和匿名身份。管理账号不带实例管理员；已有角色、Team、LDAP 和自定义角色按影响回归。
- 每操作记录入口、成功、刷新持久化、实际消费者效果、拒绝、撤权／到期；固定屏障覆盖领取、披露、移动、归档、停用和重跑。并发至少在 PostgreSQL 实测。
- 真实 Runner、接收端与协议客户端不可被 API 成功、数据库记录或新增测试替代。至少 OCI、一个实际常用包、artifact、Release、HTTP／SSH Git、LFS；常用包具体选择在协议包实施前据使用证据登记，不临近验收才禁用规避。
- 容量目标：单根 1,000 成员、1,000 仓、20 层、100 共享、50 用户并发、10 Runner；Linux amd64／8 vCPU／16 GiB／SSD／单应用／PostgreSQL。记录真实 Issue、PR、任务数据量。
- 常用列表／有效配置 P95 ≤ 1 秒，首个可操作页面 P95 ≤ 2 秒，长操作 2 秒内完成或返回可跟踪任务；合格空闲 Runner 两个正常轮询周期内发现任务。权限变更后的下一次授权使用新状态。
- 十仓人工对照任务冻结为：成员授予及撤销、公共 Variables 调整、Secret 轮换、Runner 管理、Hook 管理、基础规则变更和各项结果核对。两个流程使用相同输入、结果、异常样本与顺序；分别统计人工活跃时间、重复操作、错误及介入，机器等待单列。总活跃时间和重复操作均须减少至少 80%。当前尚无人工实测，不估算填通过。
- 固定样本内误授权、误拒绝、凭据泄漏为零；有成立 P0／P1 则安全 FAIL。核心操作全部有证据且容量和效率合格才算一期完成。P2／P3 与环境未验证单列。

实际命令、环境和阶段证据记入[验收记录](group-subgroup-phase1-acceptance.md)，最终代码审查另行记录。当前不作一期完成或候选发布声明。
