# 原生审批迁移与回退说明

## 迁移前

必须对实例数据库、仓库、配置与业务数据做一致性完整备份，并在独立实例演练。先记录保护规则 ID、分支表达式、原生人数与名单、仓库/群组/实例审批规则、当前设置和未完成 PR 快照。按仓库检查名称关联是否存在、主体是否存在、必需规则人数与候选池是否相符。保留盘点和迁移前后同一 PR 的逐规则结果，不能仅看启动成功。

## 迁移行为

当前整合基线使用迁移 370（完成后数据库版本 371）。最终部署时必须核对发行包对应的迁移序号，不可手工降低数据库版本来强行启用旧程序。

迁移把每条原生保护审批配置转成同一 `ApprovalRule` 中的兼容记录；以 `native_protection_id` 防止重复插入。已有仓库名称关联转成稳定 ID。群组、实例声明式范围不预先展开。历史 PR 规则版本不改写，必要时追加稳定关联版本。历史评审、评论、提交和审计保留。

保护规则删除时清理关联；多保护共享规则保留其他关联，最后一个关联移除后停用，绝不变成适用于所有分支。保护名称修改不改变身份。旧人数超过新建规则限制时原值保留。

无法找到保护规则、主体已删除或配置无法等价表达时迁移报出具体阻断项并中止。配置变换在事务内回滚；新增兼容列可能已由数据库结构同步创建，但不会出现一半业务规则已启用。修复数据前先保留失败证据与备份，不能删除错误规则绕过启动检查。

## 验证

自动化迁移测试涵盖 101 人原生要求、审批名单、稳定关联、PR 追加版本、重复执行及异常关联事务回滚。隔离包首次启动已经执行新版本数据库初始化。现有目标内网数据库的存量迁移未实际执行，仍需用脱敏副本核对全部保护范围、人数、主体与未完成 PR 结果。

## 回退

开放写入前可以停止新实例并恢复迁移前完整一致性备份。恢复对象必须包含数据库与对应仓库/业务数据，不能只回退镜像。

开放写入后先进入维护状态、阻止新业务写入并保存现有完整数据。优先通过兼容修复前进恢复；如必须回退，需要经过验证的数据转换方案，保留新增审批、评审、PR、提交及审计。直接换旧镜像或恢复旧数据库导致新增数据丢失，不构成合格回退。

本包仅提供独立新实例启动示例，不自动覆盖既有生产卷、端口或配置。
