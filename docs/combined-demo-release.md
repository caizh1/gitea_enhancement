本次为完整离线包，包含 Gitea、PostgreSQL 镜像及启动脚本，不需要另行叠加之前的独立审批包。

## 重新部署

### 保留现有 Demo 数据

1. 进入维护窗口，暂停写入并备份数据库、Git 仓库、业务数据、原安装目录的 `.env` 与 `secrets/`。
2. 将新包解压覆盖原安装目录，保留 `.env`、`secrets/` 和原 Compose 项目名；不要删除数据卷。
3. 执行原目录的 `bash 安装并启动.sh`。若之前自定义过 `COMPOSE_PROJECT_NAME`，继续使用相同值。
4. 等待启动成功，登录后查看原群组、仓库、分支保护和审批规则。私有父组、原保护 ID 和审批人数应保留。

本修订执行审批迁移，数据库版本由 **370 升至 371**。遇到迁移阻断时保留日志与备份并停止开放写入；不要删除规则或手动修改数据库版本来强行启动。迁移后不能只换回旧镜像；开放写入前的回退需要恢复完整一致性备份。

### 全新部署

在新的目录解压，按启动脚本输入浏览器使用的服务器 IP 或域名，再执行 `bash 安装并启动.sh`。不要使用旧实例的 Compose 项目名或数据卷，否则不是全新安装。脚本仍生成随机密码并等待服务就绪。
