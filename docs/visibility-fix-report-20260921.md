# 仓库可见性与群组设置入口修复验收

日期：2026-09-21。范围：创建仓库、仓库可见性弹窗、原生群组设置链接及关联保存逻辑。

## 已修复

1. 创建仓库：可见性下拉框外多余的块级容器造成换行和左移。移除该容器，复用已有表单布局；未新增绝对定位或全局布局覆盖。
2. 创建仓库：将仅描述私有仓库的旧提示改为三种可见性及父群组限制说明。
3. 创建仓库：`.profile`、`.profile-private` 联动仍访问已删除的复选框。改为更新实际下拉框及其显示值；强制私有时不放宽隐藏字段。
4. 仓库设置：可见性弹窗按当前实际值选中，不再每次默认公开。
5. 仓库设置：内部和私有仓库同样提供名称确认输入，修复无法满足后端确认要求的问题。设为公开仍不要求确认名称；设为内部或私有由后端校验。
6. 子群组仓库：后端接受页面展示的完整仓库路径，同时兼容旧的内部所有者名称；错误路径仍被拒绝。移除输入框不适用于深层群组路径的 200 字符限制。
7. 父群组限制：所选可见性被收紧时返回明确警告，不再只显示保存成功。
8. 群组管理：原生设置按钮补齐 `/org/`，支持顶级组织和子群组。

## 验证结果

- 修复前在本机隔离实例复现：1440 像素窗口下，名称输入框左坐标为 597.90625，下拉框左坐标为 334，相差约 264 像素；输入 `.profile` 触发空对象访问错误。
- 修复后 Chromium 实际页面检查：1440、768、390 三种宽度下，下拉框与名称输入框的左侧和宽度完全一致，页面无水平溢出。已查看桌面、窄屏及弹窗截图。
- 实际通过表单分别创建公开、内部、私有仓库；重新打开设置弹窗，三种状态均正确回显，名称确认输入均存在。
- 强制私有配置下，两种特殊仓库名均不报错、不改变私有值；桌面和窄屏显示通过。
- 当前源码 Go 集成测试通过：`TestRepositoryVisibilityChange`、`TestRepositoryVisibilityGroupSettings`，总运行约 3.6 秒。覆盖错误确认拒绝、公开无需确认、内部与私有切换、子群组完整路径、父群组限制警告、顶级及子群组设置链接、Owner 允许与普通成员拒绝。
- 浏览器回归用例 `tests/e2e/repo.test.ts` 中“创建仓库的可见性对齐与名称联动”通过，覆盖三种宽度、特殊名称及普通名称、可见值同步和脚本错误。
- 前端生产构建通过；本次修改文件的 ESLint 和全量 TypeScript 类型检查通过；Go 新增差异检查为 0 项；差异空白检查通过。
- 全仓库 `make lint-go` 有 62 项既有问题，本次两个 Go 文件不在报告中；全仓库 `make lint-js` 也被既有代码及工作区原有脚本的 483 项诊断阻断。未扩大修改范围。

## 验收边界

浏览器使用本机隔离的治理镜像 `1.27.3+governance.demo.r5`，挂载当前模板和本次构建的前端资源；后端变更由当前源码集成测试验证。未将既有镜像视为本次后端交付包。

已检索相同左右表单中的额外块级包装及群组设置地址，并查看创建、迁移、派生与组织创建模板；未发现第二处相同的包装错位或遗漏 `/org/` 的群组设置按钮。这不等于全站所有页面均完成视觉验收。

Firefox 本机缺少浏览器运行时，未验收；用户实际 Windows 浏览器和服务器尚未验收。本次未发布、未部署。
