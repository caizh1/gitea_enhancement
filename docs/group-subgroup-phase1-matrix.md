## 记录规则

基线、范围与差异见[一期计划](group-subgroup-phase1-plan.md)。本表不是整体验收通过报告。状态区分“真实 UI 子项通过；全矩阵未验”“自动化子项通过；真实 UI 未验”“真实 CLI 通过；其他环境未验”和“未验证（本行真实操作）”；一个正例只覆盖该行明列的身份、入口、消费者和生命周期。源码存在、包编译、自动化测试、真实客户端、浏览器操作及容量结果各自记证据，不能相互替代。v5 的 Team／LFS、v6 的成员自退、v7／v8 的组织触发取消与重跑、最后 Owner 反馈、撤销邀请 HTML 404，以及 v8 受保护 Secret 三种真实 Runner 探针均有各自证据；v9 审计过滤／导出和祖先 Runner 暂停／恢复、v10 内部群组申请与旧别名 HTTP Git、v11 空组延迟删除恢复、同名子群组转移及多来源成员撤权、v12 审计员撤权与范围导出、v13 带仓库后代的归档恢复及 Generic UI 删除也有真实子项。v13 另补继承 Developer 的 Web／API／HTTP Git 与作业 token 跨仓 Code 读；v14 修复并实测 Actions 归档删除拒绝；v14／v15 补原生资料、OAuth／屏蔽入口，v15 补 push 事件提交与定时计划的真实 Runner 子项，详见对应操作行。原始群组／成员 Hook 事件及子树制品聚合分别保留为计划 D-24／D-25 差异，不以现有 Hook 继承或包导航视为完成。Runner v1.0.8 不支持 `github.ref_protected`／`gitea.ref_protected` 表达式。目标 Linux amd64、8 CPU、16 GiB 容量环境用户明确暂无，人工效率降低 80% 亦无对照实测。

来源／范围代码：G＝本组及合法子树的直接、继承、共享授权并集，按各来源能力限制；R＝目标仓库及原生 Team／协作者／共享有效能力；C＝资源所在群组的祖先配置链（共享边不进入）；L＝当前归属、归档／删除状态、修订及有效身份。每行引用这些定义作为范围与授权来源，来源字段本身也鉴权。

共同用例 V：入口可达→有权成功→刷新保留→实际消费者生效→无权拒绝→撤权／到期再检查。执行后填写实际用例函数或证据链接，下面的用例编号是验收要求，不冒充已运行测试。
